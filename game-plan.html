    A. Game overview and player fantasy

    Who you are. Tier 1 (L1–L6): you are Bob, one developer running Claude Code inside a single ~5-hour session, learning one knob at a time. Tier 2 (L7–L11): Bob is now a team lead running a week — three tickets, coffee breaks, overnights; time and cache TTLs become the enemy. Tier 3 (L12–L13): you are the budget manager for a 5-dev fleet over a month; you set policy weekly, not per turn, and finally you read a real-format diagnose report and execute the recovery.

    Core loop (one paragraph). From the level map you enter a level. A short LEARN beat replays a scripted ledger twice — without and with the level's one new tool — showing the dollar delta (the only place teaching chips are allowed, per spec 8.0's ladder exception). Then PLAY: the config strip shows only the controls unlocked so far plus this level's new one; you set your loadout, then step the SDLC unit queue — each Run Next visibly emits priced requests onto the tape, the wallet drains, compaction/rebuild badges fire, idle gaps interrupt. At queue end (or death) the GATE is judged purely from state.ledger/state.hidden/state.idleLog: pass earns 1–3 stars and unlocks the next level (which reveals exactly one more control); fail routes to a mini-report naming the hidden bucket that killed you, with one citation and a Retry button.

    One sentence per tier.

    • Tier 1: "Every token is read, written, or generated — and the multipliers (0.1x / 1.25x / 2x / 5x, C1) decide everything."
    • Tier 2: "The cache is a clock: TTLs, idle gaps, and session starts are where real money leaks ($575/mo idle, C14)."
    • Tier 3: "At fleet scale you cannot micromanage — you rank the levers by dollars (C17 ordering) and set policy."

    B.2 Persistent state

    CampaignState (already defined in src/game/levels.ts) is the only persisted object.

    • Key: localStorage["cc-sim-campaign"], versioned { v: 1, ...CampaignState } per spec 11.2.

    • Per-run replay save (SaveFile in game/types.ts) is NOT persisted in v1 (kept for tests only).

    B.3 Composition with the existing reducer

    C.2 Progressive disclosure rule (computed, not hand-listed per level)

    // src/game/shell.ts
export function unlockedControls(campaign: CampaignState, current: LevelId): ControlId[] {
  const idx = LEVEL_ORDER.indexOf(current);
  return LEVELS.slice(0, idx + 1).flatMap(l => l.introducedControls);
}
    • The config strip renders ONLY controls in this list. Locked groups are ABSENT, not greyed

    (spec 11.1: "the player cannot see tools they have not earned"). A group header renders only if it has ≥1 visible control.

    • cfgLocked fields render but are disabled with the scenario value (used only where the

    scenario forces a value, e.g. L5 forces who: "subagent").

    • Free Play uses unlockedControls(campaign, lastUnlockedLevel); post-L13 Sandbox = everything

    plus scope/seed controls.

    • L1 shows zero controls: the strip collapses to just the RUN group (Run next unit button).

    "Bob codes it by hand" first appears in L2 (it is meaningless in L1 where the budget is infinite).
